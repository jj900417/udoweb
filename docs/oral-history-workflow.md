# 구술사 수집·공개 운영 체크리스트

> 이 문서는 **운영 절차와 데이터 처리 원칙**이다. 법률 문서(동의서 양식)가 아니다.
> 실제 동의서는 법률 자문을 받아 별도로 만들고, **이 저장소에 보관하지 않는다.**

## 왜 이렇게까지 하나

구술 자료는 한 번 잘못 공개되면 되돌릴 수 없다. 말한 분과 그 가족의 삶에 남는다.
"기록을 남긴다"는 목적이 "동의 없이 공개해도 된다"로 미끄러지지 않게, 절차를 고정한다.

## 1. 인터뷰 전

- 무엇을 왜 기록하는지, 어디에 쓰일지 **말로 설명하고 시간을 드린다.**
- 동의 범위를 항목별로 확인한다. 전부/전무가 아니라 **항목별**이다:

  ```
  □ 이름 공개(실명 / 가명 / 비공개)
  □ 사진 공개
  □ 음성 공개
  □ 영상 공개
  □ 웹사이트 게시
  □ 전시 사용
  □ 출판(도록·책) 사용
  □ 상업적 사용
  □ 사후 공개 여부
  □ 공개 중단 요청 방법(누구에게, 어떻게)
  ```

- 공개 중단은 **언제든 가능**하며 그 방법을 알려드린다. 이건 형식이 아니라 약속이다.

## 2. 녹음

- 보존용 원본(Archive Master)은 가능한 고품질로: WAV 48 kHz / 24-bit, 가능하면 영상도.
- 현장 메모: 날짜·장소·면담자·동석자·주제. 인물의 연락처·주소는 **웹 데이터에 적지 않는다.**

## 3. 정리

- 전사(轉寫)는 제주어 원문을 **들리는 대로** 남긴다. 표준어 옮김은 별도 필드
  (`standardKorean`)로, 확신이 없으면 비워 둔다 — 지어내지 않는다.
- 발췌 클립은 맥락을 자르지 않는다. 오해를 부를 편집을 하지 않는다.
- 편집자 주(`context`)로 배경을 적되, 말한 분의 말과 구분되게 둔다.

## 4. 공개

- 데이터의 `consent.scope` 가 `public` 일 때만 웹에 나간다(코드가 강제).
- 실명 비공개면 `anonymized: true` + `displayName` 만 쓴다. **다른 필드에 실명을 적지 않는다.**
- 공개 후에도 본인·유족의 중단 요청이 오면 즉시 `publishStatus` 를 내리고 파일을 내린다.

## 저장소에 넣지 않는 것 (절대)

- 동의서 원본·스캔
- 전화번호·주소·주민등록번호·계좌
- 유족 연락처
- 내부 계약서
- 원본 master 파일과 그 저장 경로
- 미공개 전사 전문

→ 이런 항목은 타입에 **필드 자체가 없다**(`src/archive/types.ts`). 칸이 있으면 언젠가 채워진다.

## 내부 보존 vs 공개 웹

| | 내부 보존(비공개 저장소·오프라인) | 공개 웹(이 저장소) |
|---|---|---|
| 원본 음성/영상 | WAV·원본 영상 | ✗ |
| 전사 | 전문 | 발췌 + 필요한 만큼 |
| 개인정보 | 동의서·연락처 | ✗ |
| 메타데이터 | 전체 | 공개 항목만 |
